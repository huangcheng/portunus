# Portunus Design Context

## Design Context

### Users

Portunus serves a solo technical operator managing a private MCP gateway in short, task-focused sessions. They connect apps, probe available tools, create agent keys, and leave. The interface should create confidence, control, and clarity without pretending to be a multi-tenant analytics product.

### Brand Personality

Precise, architectural, assured. Portunus should feel like a purpose-built control room for infrastructure: distinctive and memorable, but never playful, ornamental, or vague. Operational language stays direct and specific.

### Aesthetic Direction

Use an architectural control-room direction: deep-ink framing, warm porcelain working surfaces, chartreuse accents, strong editorial typography, geometric gateway motifs, and varied compositions for overview, featured apps, and working inventories. Use a light primary workspace with repeated dark structural elements rather than an indiscriminate full-dark theme.

Avoid generic minimal admin templates, uniform white card grids, tiny low-contrast typography, purple-blue gradients, glassmorphism, decorative SaaS analytics, fake metrics, marketing-style feature sections, billing/teams/projects UI, and excessive animation.

### Design Principles

1. Make the gateway concept visible through composition, geometry, and language—not decorative effects.
2. Give overview, featured, and working content different visual weights; avoid repeating identical cards and headers.
3. Use real operational data only. Never invent activity, health, timestamps, or telemetry.
4. Preserve compact task efficiency, readable technical metadata, keyboard access, responsive layouts, and reduced-motion support.
5. Use one confident accent and deliberate typography instead of adding more colors, shadows, or effects.
