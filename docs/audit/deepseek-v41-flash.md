## 1. Verdict
**GO WITH FIXES** — the TOML/live split and runner-side trust model are the right shape, but v1 ships an unimplementable conflict remedy, a hash-then-exec TOCTOU, and an egress knob that exists only as prose.

## 2. Critical risks
- **§7 reserved-slug remedy is unimplementable.** "Rename the custom server before shipping that recipe" needs a rename API that §4 defers ("if added") and §13 defers again. Startup should hard-fail on collision instead.
- **TOCTOU on the install script.** §8.1 step 3 hashes the local script, then execs it separately. Hash the *fd* (`O_NOFOLLOW`) and `fexecve`, or copy to scratch and exec the copy.
- **`content_sha256` is not a control against a bad script.** The installer uid executes it and can write anywhere in `bin/`/`skills/`; hash bounds only the final artifact. Say so explicitly, or reviewers will over-trust it.
- **Two drift regimes on one recipe.** argv is frozen, `env_defaults` + manifest body are live → a recipe that gains an env var injects nothing on old servers, silently. No mismatch detector.
- **Synchronous Connect + 30s lock wait inside a 120s install on the spawn path**, no backoff. Spawn storms degrade to `install_lock_timeout`.
- **`history` pins are a permanent downgrade allowlist.** A compromised gateway replays old tuples forever. State the bake/expiry trade-off.
- **Migration gap:** servers created between map generation and cutover are unmapped → job aborts; no re-map path.

## 3. Contradictions / stale claims
- §3 "no operator-authored TOML" vs §7 `PORTUNUS_APPS_DIR` replacing the packaged set — that *is* operator-authored recipes.
- §4 tree snapshot carries `path`; §8.3 never uses it. Dead field that invites conflation with `install_as`.
- §4 freezes `command`/`args` but not secret *names* in `spec`; removing a name breaks old servers with no error contract.
- §6 sample shows `content_sha256` and `content_by_arch` in one block behind "# OR:" — uncommenting both is a startup failure. Footgun in the normative example.
- §8.3 "re-run only if egress allowed" — no config defines that.
- §8.3(1) skips artifacts when `recipe_slug` is NULL, but nothing forbids a NULL-recipe row holding a non-empty snapshot.

## 4. Missing requirements
- `snapshot_version`; `history` entry schema (same shape as `entries`?); pin-map `version` bump rule; pin map generated by CI, not hand-written.
- §11 has codes only — no HTTP status mapping for Connect/spawn; missing `pinmap_invalid`, `artifact_snapshot_missing`.
- Gateway per-site ensure cache: no invalidation on runner restart/re-image. Needs a runner instance id / epoch.
- Startup detection for custom-slug ↔ new-recipe collision.
- Migration: re-map path for in-flight servers; `catalog_apps_export` schema.
- `install_as.lock` location, disk-full behavior, sidecar write perms.

## 5. Design notes
Runner-executes/gateway-orchestrates is correct. Per-`install_as` flock is the right granularity. Airgap short-circuit is sound, but "fail closed when egress disallowed" needs a real knob, else it is undefined behavior. Pin-map integrity equals deploy integrity — acceptable in v1 *only* if CI derives it from TOML and scripts are reviewed; signed maps are not optional forever.

## 6. Top 5 edits
1. §8.1(3): open+hash+`fexecve`, no path re-open.
2. §7: add a rename API in v1, or make startup fail on reserved-slug collision; delete the impossible remedy.
3. §4: add `snapshot_version`; invariant `snapshot ≠ [] ⇔ recipe_slug ≠ NULL`.
4. §8.1/§8.3: define egress policy config and cache epoch per runner instance id.
5. §11: status-code mapping + `pinmap_invalid`, `artifact_snapshot_missing`; fix the §6 XOR example.
